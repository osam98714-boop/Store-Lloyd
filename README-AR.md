# LF BOTS — نسخة التصميم الجديد وربط الطلبات

هذه النسخة تحافظ على اسم LF BOTS، وتعيد تصميم الواجهة لتقترب من الصورة المرجعية، وتضيف API على Vercel لقراءة المنتجات وتسجيل الطلبات وإدارتها عبر GitHub.

## الملفات
- `index.html`, `style.css`, `script.js`: واجهة المتجر.
- `admin.html`, `admin.style.css`, `admin.script.js`: لوحة الإدارة.
- `api/products.js`: قراءة وإضافة وحذف المنتجات.
- `api/orders.js`: تسجيل الطلبات من الزوار وعرضها للمدير وتأكيد الدفع/حذف الطلب.
- `api/admin-auth.js`: التحقق من بيانات دخول الإدارة.
- `api/_github.js`: اتصال GitHub من الخادم فقط.
- `products.json`, `orders.json`: ملفات البيانات.

## إعداد Vercel — مهم
في مشروع Vercel افتح **Settings → Environment Variables** وأضف:
- `GITHUB_TOKEN`: رمز GitHub جديد بصلاحية Contents: Read and write للمستودع المطلوب.
- `GITHUB_OWNER`: اسم مالك المستودع.
- `GITHUB_REPO`: اسم المستودع.
- `ADMIN_USER`: اسم مستخدم الإدارة الذي تختاره.
- `ADMIN_PASSWORD`: كلمة مرور جديدة وقوية للإدارة.

بعدها أعد نشر المشروع **Redeploy**. لا تضع `GITHUB_TOKEN` داخل HTML أو JavaScript ولا ترسله لأي شخص. إذا كان الرمز القديم قد وضعته في ملفات الموقع أو نشرته، ألغِه من GitHub وأنشئ رمزًا جديدًا.

## إعداد GitHub
تأكد من وجود `products.json` و`orders.json` في جذر المستودع. النسخة الحالية تقرأ/تكتب ملفي JSON عبر GitHub API. استخدم مستودعًا خاصًا أو تأكد من عدم تخزين بيانات العملاء في مستودع عام؛ الأفضل مستودع خاص لأن `orders.json` يحتوي على بيانات تواصل.

## ملاحظات
- الطلب لا يعتبر مدفوعًا حتى تضغط الإدارة على «تأكيد الدفع».
- واجهة المتجر تعرض المنتجات من `/api/products`، ثم تستخدم `products.json` كخيار احتياطي للعرض فقط.
- API الطلبات تكتب إلى `orders.json` على GitHub؛ لذلك يحتاج رمز GitHub إلى صلاحية الكتابة.
- هذا حل خفيف مناسب كبداية. تخزين الطلبات في GitHub JSON قد يتعرض لتعارض إذا وصلت طلبات كثيرة في اللحظة نفسها؛ عند زيادة الاستخدام انقل الطلبات إلى قاعدة بيانات مثل Supabase/Neon.
- بعد النشر اختبر طلبًا تجريبيًا من نافذة خاصة/جهاز آخر، ثم افتح لوحة الإدارة وتأكد من ظهوره.
